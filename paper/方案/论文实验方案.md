# 论文实验方案：分工边界六档阶梯

> **本文件的范围**：只放论文实验的设计，与 `cardgen-proto` 原型的实现方案完全分离。
> - 原型实现路径 = `AI卡片生成架构方案-v3.md`（P1~P7，唯一一条）
> - 本文 = 同一套程序、不同介入时机的六个实验条件（L1~L6）
> - 原型不是本文任何一档的"标准答案"，它是 L6 的近似实现（差异见 §7）
> - **用词纪律**：正文一律用中文口语，不写 baseline / ablation / arm 这类英文缩写（统计方法名、外部论文的原文标题除外）
> - **2026-11-12 增补**：§16 数据分法、§17 工程结构（含 §17.6 命名约定）、§18 用词纪律、§19 严谨性约束（含 §19.7「目录与命名必须持续与论文对应」这条长期原则）——这四章管"怎么做才经得起审"，不改变 §1~§15 的实验设计

---

## 1. 研究问题

一句话：**卡片生成的五个阶段里，哪些交给大模型才是有效的？**

一条卡片从一句话到可渲染产物，要经过五个阶段：

| 阶段 | 做什么 | 是决策吗 |
|---|---|---|
| **内容** | 用户这句话里有哪几条信息、各是什么类型、分属哪些业务对象 | 是（理解语义） |
| **结构** | 用哪个骨架、每条进哪个槽、每槽几条 | 是（选版式） |
| **几何** | 字号、行高、换行、截断、丢哪一条 | 是（算实际占位） |
| **主题** | 四套色板选哪一套、各角色填什么色 | 弱决策（领域 → 色板的映射） |
| **发射** | 把定下来的树写成协议规定的三行 JSONL | 不是（纯序列化） |

前三个阶段是真正的决策，后两个是装配与输出。但后两个同样可以交给模型——交给模型就会出错，出错就要被量到，所以一并进阶梯。

三个 RQ：

- **RQ1**：逐个把阶段移交给程序，哪一步收益最大？
- **RQ2**：事后补救能不能替代分工？（最强的对照方案长什么样）
- **RQ3**：代价是什么（token、延迟、调用次数、修复轮数）？

## 2. 六个条件

排法是**从末端往前逐个移交**：模型做前缀，程序做后缀。

| 代号 | 名称 | 内容 | 结构 | 几何 | 主题 | 发射 | 调用 |
|---|---|---|---|---|---|---|---|
| **L1** | 一次全包 | 模型一次生成整张卡（五段合一，无阶段划分） | | | | | 1 |
| **L2** | 五段全模型 | 模型 | 模型（自由写树） | 模型 | 模型 | 模型 | 5 |
| **L3** | 发射归程序 | 模型 | 模型（自由写树） | 模型 | 模型 | **程序** | 4 |
| **L4** | 主题归程序 | 模型 | 模型（自由写树） | 模型 | **程序** | 程序 | 3 |
| **L5** | 几何归程序 | 模型 | 模型（自由写树） | **程序** | 程序 | 程序 | 2 |
| **L5b** | 结构改为从 14 选（补充） | 模型 | 模型（14 选 1） | 程序 | 程序 | 程序 | 2 |
| **L6** | 仅内容归模型 | 模型 | **程序** | 程序 | 程序 | 程序 | 1 |

读法：

- 从 L2 到 L6，**每一档只把一个阶段从模型移交给程序**，所以相邻两档的差异永远只有一个因素。这是这张表最重要的性质。
- **L1→L2 是另一件事**：不是移交，而是**分阶段**——同样全模型，从 1 次调用变成 5 次。它单独回答"拆成阶段本身有没有用"。
- **L1 那一行不列阶段名**：五段是同一个动作，模型一口气输出终产物；给它编五个中间表示，那已经是 L2 了。
- **L5b 是补充实验**，不进主表：它与 L5 只差结构阶段内部的实现（自由写 → 从规范的 14 种布局里挑），用来回答"是不是只要给模型缩小选择空间就够了"。
- **主题与修复两列不参与移交**：修复在所有档恒开（§2.1），是共同约束不是变量。
- **校验不在表里**：它不改变产物，只记录问题，每次生成都执行、所有档完全一样。它属于**度量**，不属于设计选项。

**为什么只走"从末端逐级移交"这条线，而不是枚举全部 2⁵ = 32 种组合：**

1. 这条线对应一个可检验的假设——**越靠后的阶段越依赖具体数值与格式，越适合程序；越靠前的越依赖语义理解，越适合模型。** 阶梯的任务就是找到这个假设在哪一步翻转。
2. 每档只动一个阶段，测的是**边际贡献**；全枚举测的是交互效应，成本翻五倍、结论更散。
3. 非前缀组合（例如"结构归程序、几何归模型"）在工程上少见且问题未变：程序定下骨架后，模型去填字号仍然拿不到真实宽度。这类组合写进限制，作为未来工作。

### 2.1 修复为什么不在阶梯上

修复和分工是两条不同的轴。六档之间只移动"谁的活"，修复不属于这条轴——把它做成阶梯上的一档，会让读者发现"这一步动的不是分工"。

所以：

- **六档里修复恒开（程序修复）**，对所有档一视同仁。这是**保守**做法——让最强的对照方案带着修补上场，赢了才可信；
- **修复本身作为 RQ2 单独检验**（§8），不进阶梯。

### 2.2 修复是什么：程序修复，不是模型修复

"修复"有两个完全不同的东西，必须先分开：

| | 程序修复 | 模型修复 |
|---|---|---|
| 做法 | 读违规清单，按已知规则改（缩字号、截断、删条目、换骨架、降档） | 把违规清单连同产物回灌给模型，让它重写 |
| 需要模型调用 | 不需要 | 需要（本质是第二次生成） |
| 确定性 | 完全确定，可复现 | 不确定，同一输入可能修出不同结果 |
| 能改什么 | 只能做局部补丁，改不动结构 | 能重写结构，也能改内容 |
| 成本 | 毫秒级 | 一次完整生成的 token 与延迟 |

主阶梯里的一律是**程序修复**。模型修复只在 §8 作为"最强补救"出现，并且必须**在等 token 预算下比较**——否则"多花几倍钱换来提升"不是结论。

## 3. 逐档定义

| 代号 | 模型做什么 | 程序做什么 | 主要失效模式 | 需要的新实现 |
|---|---|---|---|---|
| **L1** | 读 query，直接输出完整三行 JSONL（组件树 + 数据模型 + 渲染指令）；白名单、字号档、间距档写在提示词里；颜色只写占位符 | 解析 + 校验 + 程序修复；色值按领域填入 | 越界、裁切、白名单外组件、丢字段；修补后仍残留结构性错误 | 全包提示词 + few-shot + 校验器 + 修复器（1~2 天） |
| **L2** | 五次调用依次做：语义计划 → 组件树 → 每个文本节点的字号与截断 → 色板与色值 → JSONL 文本 | 逐段解析 + 校验 + 修复 | **任一段产出不合规就断链**；几何几乎必错（模型拿不到真实渲染宽度） | 五段提示词 + 四个中间表示的解析器 |
| **L3** | 同 L2，但止于"带色值的树"，不写 JSONL | 把树序列化成 JSONL + 校验 + 修复 | 树合法但序列化字段名/嵌套写错 | 树的 schema + 序列化器 |
| **L4** | 同 L3，但止于"带字号的树"，只选色板 id | 按色板 id 着色 + 序列化 | 色板与领域不符（例如日程卡选了蓝） | 色板枚举 + 领域映射说明 |
| **L5** | 同 L4，但止于"组件树"，字数与断行由程序算 | 从任意树重算字号/换行/截断/丢弃 + 着色 + 序列化 | 模型自己造的结构本身装不下（5 个区塞进 150×150），重算也救不回来 | 后处理器：在任意树上跑排版（250~350 行） |
| **L5b** | 同 L5，但结构不是自由写，而是从规范登记的 14 种布局里挑一个（附每种布局的适用条件） | 同上 | 选了容量不匹配的布局（5 条内容选了 S-center）→ 只能降档或截断 | 提示词 +1 字段 + 布局目录说明 |
| **L6** | 纯语义：领域、条目（类型 + 字段名）、业务对象、动作 | 从归一化起全包：规则路由骨架、装配、几何、主题、发射 | **语义抽取错**（重复值、丢标签、值截断），程序无法从语义错里恢复 | 原型现状 |

## 4. 评价指标设计

不同档的错误分布不同，用单一"成功率"会掩盖**错误类型迁移**——L1~L5 的错在几何与协议，L6 的错在语义保真。所以指标必须分层、且每一项都要说清"它能说明什么、不能说明什么"。

### 4.1 三条设计原则

1. **每个因变量都要有指标，每条指标都要能自动判定。** 判不了的（例如配色是否得体）不用代理指标硬凑，直接写进 §4.6。
2. **测量只看产物，不看中间状态。** 校验器只吃 A2UI + query + 外部基准，不读流水线的 plan。理由很实际：L1 根本没有 plan，如果基准依赖 plan，四组之间就不可比。
3. **基准必须独立于被测系统。** 内容对错的判定基准来自金标数据，不能来自被测系统自己的输出——否则等于自评。

### 4.2 三组指标总表

| 组 | 指标 | 单位 | 数据来源 | 回答 |
|---|---|---|---|---|
| **A 正确性** | A1 协议合规率 | % | 校验器（流水线内） | RQ1 |
| | A2 几何越界 | 像素 / 节点数 | 真实排版测量（流水线外） | RQ1 |
| | A3 最小可读字号 | fp / 越界节点数 | 同上 | RQ1 |
| | A4 内容覆盖（漏了多少） | % | 外部基准对照 | RQ1 |
| | A5 内容保真（编了多少） | % | 外部基准对照 | RQ1 |
| | A6 重复值 | 处 | 产物文本 | RQ1 |
| | A7 结构一致率 | % | 与人工参考骨架比 | 仅趋势 |
| **B 代价** | B1 端到端时延 P50 / P95 | ms | 请求日志（分阶段） | RQ3 |
| | B2 模型调用次数 | 次 | 请求日志 | RQ3 |
| | B3 token（输入 / 输出） | 个 | 模型客户端 | RQ3 |
| | B4 每张合格卡的成本 | token/张 | B3 ÷ 合格卡数 | RQ3 |
| | B5 修复触发与轮数 | 次 | 校验日志 | RQ2 |
| **C 稳定性** | C1 字段翻转率 | % | 重采样（N=10，温度 1.0） | RQ1 佐证 |
| | C2 产物逐字一致率 | % | 重采样 | RQ1 佐证 |

> 每项指标的实际取数工具、记录字段与口径细节（双向包含 / 数字边界 / 复合值拆分）见原型文档 §7.0.2「度量工具链」。论文正文只写指标定义与统计方法，工具链属于复现材料。

> **命名约定（避免三套字母混用）**
> - **指标编号** = 组字母 + 序号：A 正确性（A1~A7）、B 代价（B1~B5）、C 稳定性（C1~C2），共 14 项——口语里说的"尺子"就是它们，两者完全等价。
> - **待办编号** = `T01`~`T21`（Task），见 §14。T 是任务，一行一个动作，有完成判据。
> - **严重程度** = `P0` / `P1` / `P2`（Priority），见 §12。P 是"这个问题有多要命"，不是任务。
> - 一个 P 问题可以拆成多个 T（例：P0-4 拆成 T09），也可以并入别的 T（例：P0-5 并入 T08）。
> - §4.7 的四个等级与 §14 的四个分组**不用字母**，直接用中文名（硬/准硬/有偏/参考；口径组/实验组/结构组/写作组）。

### 4.3 逐项定义

**A1 协议合规率**：`violations` 为空的卡 / 总卡数。同时按 `code` 分组报告（哪类违规最常见），只看总数会丢掉"错误从几何迁移到协议"这类信息。

**A2 几何越界**：真实排版后，文字节点超出 root 边界的像素和；另报"溢出 > 4px 的节点数"（≤4px 与金标同级，不计缺陷）。

**A3 最小可读字号**：全卡最小字号；**报两条线**（口径 C-05）——低于 12fp 的节点数（UX 规范线，判违规）与低于 10fp 的节点数（金标实测线，判"比金标还差"；金标自身存在 10fp 的卡，只用 12fp 一条线会得出"金标不合格"的自相矛盾结论）。这一项专治"靠缩字号塞进内容"。

**A4 内容覆盖（recall）**：设该卡应有事实集 `F`。`F` 来自**金标终产物**（`qN.jsonl` 的 `updateDataModel.value` 里的叶子值，字符串/数字，排除 code/id 一类机器值，复合值按分隔符拆开），对被评测的每张卡从它的金标产物里逐卡抽取（报告题集 250 卡，跑批前一次性生成，不手工维护）。一条事实算命中，当且仅当它的**值**出现在卡面文本里（去空格、全/半角归一后比对）。**拆两档**（口径 C-02）：A4a 对全部事实（本条），A4b 只对人工写下的"该题要求必须显示的条目"（报告题集每卡 2~3 条，§16.6；未写时 A4b 显示"未量"而非 0）。主结论用 A4b，A4a 作参考。

> 为什么不用 `dataModelSchema` 的全字段：那是"数据层能提供什么"，不是"这张卡该显示什么"。用全部字段会把"没展示但也不该展示"的值算成漏，覆盖率永远上不去。用金标终产物才是"人认可的最小事实集"。

**A5 内容保真（precision）**：从卡面提取所有"数据型片段"（数字、日期、百分比、带单位的量），统计其中**能在 `F` 或 query 原文里找到出处**的比例。这一项专治编造——比如用户没说"降水 30%"，卡上却出现了。

> A4 与 A5 必须一起报。只报覆盖，模型可以靠堆砌内容刷分；只报保真，模型可以什么都不写。
>
> A5 的 0/0（口径 C-03）：卡面没有任何数据型片段时，保真记"不计入"并单独报**空数据卡数**——记 100% 会让空卡刷满分，记 0 会冤枉合法形态。排除比例本身进主表，读者能看到有多少卡未参与保真均值。

**A6 重复值**：同一值在卡面出现 ≥2 次的事实条数（"68% 出现两次"这类）。

**A7 结构一致率**：骨架与人工参考一致的比例。**只作趋势，不作主指标**——金标自身对同类内容既用 S2 也用 S5/S6，追平它没有意义。

**B1 端到端时延**：从收到 query 到产出完整三行 JSONL，**不含前端渲染**（渲染发生在设备上，另由 A2 的几何测量覆盖）。报 P50 / P95 / max，不报均值——长尾对产品更要命。同时分阶段记录：模型调用 / 程序装配 / 校验 / 修复。

**B2 模型调用次数**：L1-M 要 2~3 次。不单列这一项，时延与 token 的横向对比就没有意义。

**B3 token**：输入 / 输出分别记。

**B4 每张合格卡的成本**：`总 token ÷ 合格卡数`。合格卡 = **复合**（口径 C-04）：协议合规 ∧ 覆盖 ≥ 阈值 ∧ 单节点越界 ≤ 4px；主阈值 80%，另报 60% / 100% 两档敏感性。覆盖优先用 A4b，未标注时降级用 A4a（表头注明）。它比"每张卡平均成本"更能反映真实代价：需要反复修的条件，单次便宜也可能整体更贵。

**B5 修复触发与轮数**：有违规的生成占比、单次平均修复动作数、**修复引入的新违规数**（`introduced_by_repair`）。最后一项是自证清白用的，必须单列。

**C1 字段全一致率 / C2 产物一致率**：同一 query 在温度 1.0 下独立重采样 N=10 次，统计每个字段"10 次取值完全相同"的比例与"产物逐字相同"的比例。**不用翻转率**（N=10 时低频变体会漏采样，单条 query 的翻转率不可信）。C1 按字段分层比：domain/size/theme 精确比；条目数比整数；条目类型比多重集；条目文案比`(type, 去空白标点的 hint)`多重集——**措辞不同算不一致**（严格口径，声明为下界）。这是"确定性"这一主张唯一能拿出的硬数据，单独成一个小实验，不混进主表。

### 4.4 聚合与统计

- **配对设计**：同一条 query 在六个条件下各跑一次，按 query 配对，不做独立样本比较。
- **二元指标**（A1 / 覆盖是否达标）：McNemar 检验，报告**不一致对数**，而不是只报准确率差。
- **连续指标**（A2 / B1 / B3）：Wilcoxon signed-rank，报告中位数差与 bootstrap 置信区间。
- **时延与成本**：报 P50 / P95 与"每合格卡成本"，不报算术均值。
- **多重比较**：主表做的是描述性比较，不宣称显著性；若做显著性检验，必须声明未做多重比较校正。

### 4.5 指标与 RQ 的对应

| RQ | 主指标 | 辅助指标 |
|---|---|---|
| RQ1 分工边界 | A1~A6 | A7（趋势）、C1/C2（确定性） |
| RQ2 补救能否替代分工 | A1、A4、A5 + B5 | B4（补救的代价） |
| RQ3 代价 | B1、B3、B2 | B4 |

**一条硬约束**：RQ1 的结论不能只靠 A1。协议合规率是最容易刷的一项（少放内容就合规），必须和 A4/A5 一起看，否则会出现"越合规、内容越少"的伪优劣。

### 4.6 明确测不到的

- **审美与配色契合度**：没有 user study，任何"好看"的打分都是自欺。配色在四组里恒为程序，本就不构成变量。
- **语义细微错误**：值正确但挂错对象（"左耳 68%" 写成 "右耳 68%"）——A4 只能判"值出现过"，判不了归属。人工抽查，写进 limitation。
- **长期使用体验**：单次生成评测覆盖不到。
- **跨域泛化**：金标只来自一套生产系统与固定的 14 种布局，不外推到其他系统或开放域。

### 4.7 尺子的审计：14 把，一把都没校准过

把 §4.2 拆到最小可判单元，一共 **14 把尺子**。按"谁能推翻它"分四级：

| 级 | 含义 | 数量 | 有哪些 |
|---|---|---|---|
| **硬尺子** | 机械可判、无可争议，换个人测也一样 | 2 | B2 调用次数、B3 token |
| **准硬尺子** | 客观，但依赖一个我们选定的口径/阈值/环境 | 7 | A1、A2、A5、A6、B1、B5、C2 |
| **有偏尺子** | 测得住、也稳定，但**测的不是我们真正想说的那件事** | 4 | A3、A4、B4、C1 |
| **参考尺子** | 已知不客观，只作描述，不进主表 | 1 | A7 |

#### 4.7.1 逐把审计

| 尺子 | 判据形态 | 客观性：谁能推翻它 | 已知偏差 | 想刷高它最省力的做法 |
|---|---|---|---|---|
| **A1 协议合规率** | 机械（规则确定，二值） | 只有"规则集本身"能推翻——**规则漏一类错，它就虚高**，而我们没测过规则的召回 | ① 分母含不含"生成失败"未定；② 规则是我们自己写的，可能过严（把合法写法判成违规）或过松 | 少放内容、少放组件 |
| **A2 几何越界** | 半机械（headless 渲染后测像素） | 渲染引擎：**我们测的是 Edge/Blink，交付目标是鸿蒙 ArkUI**，字体度量不同 → 只能算代理测量 | ① 4px 阈值是经验值（与金标同级），非物理阈值；② 只测"出界"，测不出"贴着边挤得难看" | 一律用最小字号 |
| **A3 最小可读字号** | 机械（读 `fontSize`，静态可算） | 阈值：**12fp 是规范值，但金标自身有 10fp 的卡**——用 12fp 当缺陷线，金标自己不合格，基准不干净 | 可读性是字号 × 对比度 × 行高的合成，只取字号是**单因素代理** | 删内容腾空间 |
| **A4 内容覆盖** | 半机械（子串/双向包含匹配） | 测的是什么：`F` 是"**金标显示了什么**"，不是"**这张卡应该显示什么**"。L6 因容量降级少显示一条，会被算成漏，而那是正确取舍 | ① 金标自身可能漏了重要事实；② 匹配过宽（`68` 命中 `168` 已修，但边界规则不可能穷尽） | 把所有事实堆上去 |
| **A5 内容保真** | 半机械（正则抽"数据型片段"再查出处） | 口径：什么算"数据型片段"由正则决定；"能找到出处"用双向包含，**宽松 = 上界** | ① 宽恕编造；② 值对但挂错对象完全抓不到（已在 §4.6） | 只写标题，什么都不写 |
| **A6 重复值** | 机械 | 测的范围窄：只数**数值型**重复，文字重复不算；有些重复是刻意的（标题与正文都出现地点） | 阈值 ≥2 次即算，未区分"冗余"与"强调" | 不显示重复 |
| **A7 结构一致率** | 人工（单人标参考骨架） | 全链最弱：参考是人标的，且**金标自身同类内容既用 S2 也用 S5/S6** | 追平它没有意义——它衡量"像不像另一个系统" | — |
| **B1 端到端时延** | 机械（`perf_counter`） | 环境：单机、单模型、公网。**数字不可外推**，只能同批次内比较 | 不含前端渲染（已声明），所以不等于"用户感知延迟" | 换更小的模型 |
| **B2 调用次数** | 机械 | 无人能推翻 | — | — |
| **B3 token** | 机械 | 端点：不返回 usage 时我们**如实记 None 不估算** → 该模型上 B3/B4 不可比 | 缺失而非错误，方向诚实 | 缩短提示词（可能损质量） |
| **B4 每合格卡成本** | 派生（B3 ÷ 合格卡数） | 口径：**"合格"现取"协议合规"，而协议合规恰好最容易被刷** → 这个指标会奖励"内容少的条件" | 派生指标，误差来自分子与分母两端 | 提高合格门槛，少算分母 |
| **B5 修复触发与轮数** | 机械（日志） | 依赖：修复器**还没实现**（原型 T3），`introduced_by_repair` 现在产不出来 | 触发率受规则集覆盖影响，规则漏则触发率虚低 | — |
| **C1 字段翻转率** | 统计（N=10 重采样） | **统计量选错了**：N=10 时 p=0.1 的变体有 35% 概率一次不出现，单 query 的翻转率不可信；且"字段"未定义规范化（多重集？剥离文案？） | 口径缺失导致不可复现 | 温度调 0 |
| **C2 产物逐字一致率** | 机械（哈希，已抹平 surfaceId） | 无人能推翻，但**逐字 = 下界**：语义等价、措辞不同也算不一致 | 方向保守（低估稳定性），可以明说 | 温度调 0 |

#### 4.7.2 结论一：14 把尺子里，0 把经过外部校准

所有判据都是我们自己定的：规则集自己写、阈值自己选、基准自己抽、阈值线自己画。它们内部自洽（同一个脚本跑两遍结果一样），但**没有一把和"人的判断"做过对照**。

后果很具体：如果 A4 的覆盖率与人的判断相关性只有 0.2，那么"L6 覆盖 82%、L1 覆盖 71%"这句话在论文里毫无意义——它只说明两个数不一样，不说明谁更好。**审稿人真正会问的不是"你的数是多少"，而是"你的数凭什么可信"。**

这正是 §13.4 把"指标-人评相关性"排第二的原因；本节的审计把它升级为**必做**：不做，14 把尺子全是自评。

#### 4.7.3 结论二：每把尺子单独都不可信，必须成对使用

| 想刷的指标 | 最省力的刷法 | 谁来挡 |
|---|---|---|
| A1 合规率 | 少放条目 | **A4 覆盖 + A5 保真** |
| A2 越界 | 全部用最小字号 | **A3 最小字号** |
| A3 最小字号 | 删内容 | **A4 覆盖** |
| A4 覆盖 | 把所有事实堆上去 | **A1 合规**（装不下）+ **A6 重复** |
| A5 保真 | 什么都不写 | **A4 覆盖 = 0** |
| B4 每合格卡成本 | 抬高"合格"门槛 | **冻结口径**（§4.7.4 第 1 条） |
| C1 / C2 稳定性 | 温度设 0 | **固定 1.0 并在文中声明** |

三个必须成套报的三角：**(A1, A4, A5)** 防"少放就合规"；**(A2, A3, A4)** 防"缩字就合规"、**(B3, B4, A1)** 防"便宜但没用"。

#### 4.7.4 结论三：三件修正，成本都不高

1. **冻结 6 处未定口径**（不定就永远不可比）：失败卡怎么算（覆盖 0 / 保真 None / 计入违规）、A4 是否拆 mustShow、A5 的 0/0 记什么、B4 的"合格"定义、A3 的阈值（建议报两条线：12fp 规范线与 10fp 金标线）、C1 的字段规范化细则。
2. **C1 的统计量改掉**：从"翻转率"改为"**N 次全一致率**"（10 次取值完全相同记为 1），跨报告题集抽出的 12 道重复题求比例 + Wilson 区间。理由已写在原型文档的重采样设计里：N 小时只有二值量站得住。
3. **测规则集自己的召回**：往合规产物里**注入已知缺陷**（每类违规注入 5 例），看校验器抓不抓得到，报漏检率。`tests/test_validate.py` 已有 12 项单点破坏测试，实测覆盖 15 个 code 中的 14 个（唯一未覆盖：`surface.create_surface`），把它的结果整理成"规则 × 是否可检出"的表即可，几乎零新增成本。

## 5. 预期结果与推翻条件

先写预期，再写"什么情况下结论会被推翻"。这是审稿人判断有没有挑着好看的说的地方。

| 跳跃 | 改了什么 | 预期方向 | 若结果相反，说明什么 |
|---|---|---|---|
| **L1→L2** | 分阶段（1 次 → 5 次，仍然全模型） | 变差，或持平 | 若明显更好 → "拆阶段本身"就有收益，主张要改成"分阶段 + 交程序"两件事都要 |
| **L2→L3** | 发射归程序 | 明显改善（协议合规、可解析率） | 若无改善 → L1/L2 的失败不是格式问题，格式约束的代价被高估 |
| **L3→L4** | 主题归程序 | **接近零差异**（主题本质是领域查表，领域在内容阶段已定） | 若模型版明显更差 → 主题确实不该给模型；若更好 → 我们的领域映射规则本身要改 |
| **L4→L5** | 几何归程序 | **改善最大**，主要落在越界与最小可读字号 | 若无明显改善 → "几何必须由程序算"不成立，全文主张需要重写 |
| **L5→L6** | 结构归程序 | 中等，**可能双向**：一致性上升，但结构僵硬时内容可能丢 | 若无差异 → 结构选择权不必收回，主张收紧为"数字权是关键" |
| **L5→L5b**（补充） | 结构从自由写改为从 14 选 | 中等改善，但不及 L6 | 若 L5b 与 L6 持平 → "给模型一个受限选择集"就够了，不必程序路由 |

读这张表的方法：**L4→L5 是全文的命门**。因为论文的核心主张是"几何依赖一个模型拿不到的量"，如果这一跳不显著，主张就不成立。其余几跳是它的支撑——如果只有 L4→L5 显著、其余都不显著，反而是最干净的结论：**五个阶段里只有几何必须交给程序**。

**预先声明**：本实验不主张"哪一档最好"，只主张"每一份正确性来自哪一步"。哪一档最好取决于产品更在意内容保真还是一致性，这是设计取舍，不是实验结论。

## 6. 公平性约束（缺一条，整张表作废）

1. **同一份约束清单 R**：组件白名单、字号批准档位、间距档位、色值格式、画布尺寸、root 壳要求。所有档共用同一份，不许 L1 少给。
2. **同一份 few-shot 素材**：示例数量、示例内容一致。L1 的示例要覆盖几何，否则是故意削弱。
3. **同模型、同温度、同重试预算**；记录 model version 与完成时间。
4. **迭代次数对等**：每档的提示词与代码，由同一人或同一流程、相同轮次迭代完成。这一条必须写进论文，否则"模型能不能做到"会退化成"有没有好好调"。
5. **报 token 成本**：L1 的提示词显著更长（要塞进模板库与约束），质量对比必须附成本对比。
6. **配对比较**：同一条 query 在六档下各跑一次，用 McNemar 检验，报告不一致对数（不是只报准确率差）。
7. **补救对比必须等预算**：程序修复零额外调用，模型修复要额外 token——两者比较时，要么折算成等 token，要么把成本并排列出并明确说明"这不是等预算比较"。

## 7. 与原型的关系：两个修复点

原型 `cardgen-proto` 是**一条固定路径**（P1~P7），对应表中 **L6**。它有两个修复点：

| 修复点 | 位置 | 改什么 | 在阶梯里 |
|---|---|---|---|
| **入口修复** | P1 归一化 | **改内容集合**：丢非法条目、info/action 去重、stat→percent、悬空引用清洗、未归属字段并入首对象 | 恒开，不是变量 |
| **出口修复** | 校验 + 修复 | 不改语义，只改几何与协议：缩字号、截断、降档、换组件 | 恒开，不是变量 |

### 7.1 这里有一个不对称，必须正面处理

入口修复的作用对象是"结构计划"（entries / objects）。而 L1 的模型一次输出整张卡，**根本没有计划这一层**，所以入口修复在 L1 里没有作用对象——不是不给他们用，是那层数据不存在。

这带来一个真实的质疑：**L2~L6 是不是偷偷多拿了一层修补？**

处理方式不是"保证公平"（保证不了），而是**把它量化**：报告入口修复的触发率与动作数，并在 §8 用"关掉补救"的对照把它的贡献直接量出来。

### 7.2 三个开关（只存在于代码里）

> 这些开关只用于"跑出各个条件"，**论文里一个都不出现**。论文只有"条件"，没有"开关"。判据见 §11.1。

| 开关 | 作用 | 默认 |
|---|---|---|
| `ENTRY_REPAIR` | 入口层"改内容"的几条规则是否生效 | 开 |
| `EXIT_REPAIR` | 出口层修复动作是否执行 | 开 |
| `VALIDATE` | 校验是否执行。**观测工具，不是干预**，永远开 | 开 |

**校验永远开、只有修复可关**：关掉修复之后，校验仍然能数出"原本有多少处违规"，于是可以直接测出"修复到底救了多少"。

还有一条容易忽略的细节：**关掉修复时必须同时关掉空计划兜底**。原型的 `pipeline.py` 在 M1 解析失败时会给一张占位卡（"暂无可展示的内容"），实验里这是掩盖失败——失败就该记为该条生成失败并计入协议违规。

## 8. 事后补救能不能替代分工（RQ2）

### 8.1 必做：补救的上限

在**同一个位置**（全包，即模型写树、模型算数）上给三次机会，看最强的补救能走到哪：

| 配置 | 补救方式 | 额外模型调用 | 说明 |
|---|---|---|---|
| **L1-NR** | 无 | 0 | 裸生成，只有解析 |
| **L1** | 程序修复 | 0 | 主阶梯里的那一档 |
| **L1-M** | 模型修复（≤2 轮） | 1~2 次 | 违规清单回灌，让模型重写 |

结论的写法：

- 若 L1-M 也追不上 L5/L6 → "补救不能替代分工"，这是对"削弱对照方案"最有力的回应（三次机会都给了）；
- 若 L1-M 追平 L5/L6 → 说明分工方案的收益可以被算力买回来，这是对产品很有价值的判断，也必须如实写；
- L1-M 与 L1 的差 = 程序修复相对模型修复的差距，直接回答了"该用哪种修"。

**等预算纪律**：L1-M 多花了 1~2 次调用的钱。要么按 token 折算后比较，要么把成本单列一栏并明确写"非等预算比较"。不做这一步，这条结论会被审稿人否掉。

### 8.2 可选：补救的边际价值随位置递减

如果版面和时间允许，再补两组 **L5-NR / L6-NR**（关掉入口与出口修复），与 L5 / L6 配对：

| 位置 | 无补救 | 有补救 | 增益 |
|---|---|---|---|
| 全包 | L1-NR | L1 | L1 − L1-NR |
| 自由结构（模型写树） | L5-NR | L5 | L5 − L5-NR |
| 规则结构 | L6-NR | L6 | L6 − L6-NR |

三个增益按位置排开，预期是一条下降曲线：修复能做的只有局部补丁，几何由模型猜时可修的多，由程序算出来时没什么可修。这是对 RQ1 结果的机制解释，属于加分项，不是必需。

**边界**：三对之间不能估计"分工主效应"（相邻位置差的不止一个变量），只做同一位置内的有/无补救对比。

### 8.3 三种结果，事先写好解释

| 观测 | 含义 | 怎么写 |
|---|---|---|
| L1-M 仍显著劣于 L5 | 补救的上限低于分工 | 最强结论，RQ2 收在这里 |
| L1-M 接近 L5 | 收益可被算力替代 | 承认分工不是唯一路径，并给出成本对比 |
| L1-NR 与 L1 差距很小 | 程序修复本身没起作用 | 说明 L1 的失败不是"缺修补"，而是"结构就错了" |

**必须在跑之前写下来**，否则就是事后编故事。

## 10. 威胁与限制（可直接写进论文）

- **入口修复的不对称**：L2~L6 都有计划层入口修复，只有 L1 没有对应物（那层数据不存在）。已用 §8 的对照量化，残余差异仍在 limitation 里写明。
- **单一来源、494 条**：金标来自一套生产系统，不可外推到其他业务域或开放域。
- **无 user study**：视觉适配（配色、美观）无法评估，本实验不做任何审美主张。
- **结构一致率不是质量指标**：金标自身对同类内容既用 S2 也用 S5/S6，追平它没有意义。
- **单模型单供应商**：结论不跨模型外推。
- **L1 的提示词工程投入天然更大**：即使按第 6 条第 4 款对等迭代，也难以完全消除"给全包方案写得不够好"的质疑，需在 limitation 里明说。
- **McNemar 的样本量**：报告题集 250 条配对，在"约 35% 的题两档结果不同"的情形下，能稳定检出 66:34 的差异；小于 60:40 的跳跃不应宣称有效（§16.4）。

## 11. 论文里怎么讲：章节安排与命名纪律

### 11.1 开关不进正文，但要进附录

先把关系说清：**代码里的开关状态确实组成了论文里的条件**，这一步没错。问题只在于"读者该看见哪一层"。

- **正文**讲条件（L1~L6、L1-NR、L1-M），因为读者需要的是"设计上有哪几种做法"，不是"环境变量设成几"；
- **附录**给一张"条件 → 配置"的对照表，因为不给就无法复现。这张表必须存在，否则与"代码里明明有开关"自相矛盾。

判据：一个开关如果只有一个状态，它不是开关，是实现细节，删掉、不描述；如果有两个状态，它一定对应"两个条件之间的差"——要么这个差已经是一个方案，要么它值得成为一个对照。

| 开关 | 状态数 | 正文里的处理 | 附录里的处理 |
|---|---|---|---|
| 校验（`validate`） | 1（恒开） | **不出现**。写进度量节："每次生成都执行校验并记录违规数"。它是尺子，不是变量 | 注明"校验始终开启，仅记录不修改" |
| `repair_plan` / `repair_card`（主阶梯内） | 1（恒开） | **不出现**。写成"所有条件共享同一套程序修正"，属于共同约束 | 注明四项入口修正与出口修正的具体内容 |
| 同两个开关（RQ2 内） | 2 | 变成 `-NR` 对照组（L1-NR / L5-NR / L6-NR） | 表格里写出 `false / false` 的实际取值 |

**注意不要写成笛卡尔积**：三个开关理论上有 2×2×2 = 8 种组合，实验只用了其中几组。条件是按设计挑的，不是把开关全排列跑一遍——这一点要在附录里说清，否则读者会以为漏了组合。

一句话：**正文只有条件，附录才有配置；开关活在代码和跑批脚本里，但必须留下可复现的映射。**

### 11.2 主阶梯与补救分析分开写

| 章节位置 | 放什么 | 不放什么 |
|---|---|---|
| 主实验（RQ1） | L1~L6 六档 × 分层指标 | 任何"关掉某模块"的方案 |
| 补救分析（RQ2） | L1-NR / L1 / L1-M 三组；可选加 L5-NR、L6-NR | 六档的完整表（会重复） |
| 成本（RQ3） | token / 延迟 / 修复轮数 | — |

`-NR` 与 `-M` 这些组**不是新方案**，只在 RQ2 那张表里出现，且必须写清"无补救"或"模型修复"，避免被读成产品变体。

### 11.4 术语纪律

三个说法，各管一件事，不要混用：

- **六档阶梯 = 把决定权一项项换手**。同一套程序，五个阶段在六个位置上逐个移交，比的是"位置效应"。**不能叫"拆件对比"**——拆件对比是拿掉一个部件看它的作用，前提是有没有该部件；我们的六个方案部件一个不少，只是同一件事换了人做。
- **L1 与 L1-NR 这一对 = 拆件对比**（拿掉修补、其余不变），整个实验里只有这一处配用这个词。
- **跨位置比较（如 L1-M 与 L5b）= 控制变量的对比**：只换一个条件，其余锁死。

把六档阶梯叫"拆件对比"，属于用词错误，审稿人会直接指出来。

### 11.5 外部证据：同类论文怎么摆这些组

| 论文 | 做法 | 对本方案的含义 |
|---|---|---|
| Olausson et al., *Is Self-Repair a Silver Bullet for Code Generation?*, ICLR 2024 | 把"自我修复"当成独立研究问题，与**等预算的独立采样**对比；结论是修复常不如多采样 | 补救必须单列成 RQ，且必须等预算；不能混进主对比链 |
| UIFormer（工业部署，WeChat DET，arXiv 2512.13438） | 主结果之外单设 "Ablation on Individual Components"：去掉 DSL 约束、去掉迭代精修，各做一组 | 去掉约束/去掉修补是**拆件对比组**，不是六档阶梯的一档 |
| Portal UX Agent（arXiv 2511.00843） | "Ablation: Bounded vs Unconstrained Generation" 两组对照 | 同类做法：约束有无做成两组，不做成阶梯 |
| 设计系统 UI 生成（2026 预印本，THAKI） | 四个生成组：base / LoRA / 确定性修复 / 约束解码；并报告 "Constraint Tax"（合法性↑、保真度↓） | 把"确定性修复"当成一个实验组，且如实报告代价 |

共同点：**主对比用少量强对照方案（2~4 组），修补与约束的有无放在独立的拆件对比小节**。没有一篇是把"修补"做成主对比链条上的一档。

## 12. 自审清单：不严谨之处与待办

> 按"审稿人最可能从哪里开刀"排序。P0 = 不改会被质疑到拒稿；P1 = 会被追问但可辩护；P2 = 写作打磨。
> **执行请看 §14 待办总表（唯一清单）**；本节保留"为什么这些问题存在"的论证，不再单独勾任务。

### 12.1 P0：必须先解决

**P0-1 数据泄漏：规则有没有从被评测的数据里反推**

- 旧体系的事实（已废弃）：早期程序的骨架几何、容量降级、percent 判定、排法表，全部由 49 张真实卡反推，又在同一批上评测。这批数据与它反推出来的规则现在整体退役。
- 现在的做法：规则按 UX 规范（`cardgen-proto/ux-spec/UX-SPEC.md`）重新实现，容量常数直接取规范附录 A 的参考预算，不从数据拟合（§16.4）。
- 残余风险（必须承认）：开发题集 100 条的答案在写提示词示例时被作者看到，而它与报告题集同源。所以严格说，"提示词示例"仍受开发题集影响。
- 处理：① 机制与常数来自规范；② 报告、扩展、保留三个题集的答案在首次跑批前移出工作区（§16.7）；③ 上述两条边界写进论文。
- 涉及：§6 公平性、§10 威胁、§16。

**P0-2 单一模型、单一供应商**

- 事实：所有结论只在一个模型上得出。这是 ASE 的 LLM 论文里排前二的拒稿理由。
- 建议：至少加一个**不同家族**的模型，在 20 条子集上跑 L1 与 L6，只验证"方向一致"（不要求数值相同），写进 §5 的鲁棒性小节。成本约 1 小时。

**P0-3 统计：多次比较没有校正**

- 事实：4 档 × 6 个 A 组指标 = 十几次比较。§4.4 只说"不宣称显著性"，但 RQ1 的结论必然需要显著性。
- 建议：预设**一个主指标**（复合"合格卡率" = 协议合规 ∧ 覆盖 ≥ 80% ∧ 无 >4px 越界），主结论只对它检验；其余用 Holm 校正并明确声明。同时报差异大小与 bootstrap 置信区间，不只报 p。
- 涉及：§4.4、§5。

**P0-4 A4 只测"漏没漏"，测不出"该不该显示"**

- 事实：`F` 是金标终产物里出现的值，只能判"有没有出现"。L6 因容量降级少显示一条时会被算成漏，而那可能是正确取舍。
- 建议：拆成两个口径——**A4a 覆盖**（对 `F`）+ **A4b 必显覆盖**（对人工写下的"要求必须显示的条目"，报告题集 250 卡、每卡 2~3 条，约 3~4 小时）。主结论用 A4b，A4a 作参考。
- 涉及：§4.3。

**P0-5 L1 的提示词预算天然更高，现在只写了"要报 token"**

- 事实：L1 必须把组件白名单、字号档、间距档塞进提示词，L2~L6 不需要。这是结构性不对称，不是疏忽。
- 建议：把"输入 token / 提示词长度"列为**条件属性**在表 3 单列，并在 §10 明说"这项差异无法消除，只能量化和披露"。
- 涉及：§6、§10。

**P0-6 格式约束的代价：L1 的劣势可能来自提示词格式，而不是分工**

- 事实：EMNLP 2024《Let Me Speak Freely?》证明格式约束会显著损害推理能力（"reasoning tax"），约束越严掉得越多，字段顺序打断思维链时最严重。L1 恰好把 schema 与排版规则全塞进提示词。
- 后果：若 L1 表现差，有两种解释无法区分——决策交给模型真的更差，还是**格式把模型压坏了**。后者一旦成立，主结论（"分工越靠右越好"）就被削弱。
- 建议：补 **L1-NL** 对照（模型自由文本写计划 → 程序转三行 JSONL）。它与 L1 只差"格式施加时机"，与 L5 只差"数字由谁算"，两头都能解释。另把输入 token / schema 字段数 / 嵌套深度作为解释变量列进成本表。
- 涉及：§3（L1 定义）、§4（B 组）、§10。

### 12.2 P1：会被追问，但可辩护

**P1-1 拆件对比没有独立成节（即"RQ2 里到底有没有拆件对比"）**

- 现状：§8 混了两件事——**补救上限**（L1-NR / L1 / L1-M，属对照方案强化）与**拆件对比**（L6 vs L6-NR，属"移除组件测贡献"）。
- 顶会惯例是分开的：UIFormer 单设一节"逐部件拆件对比"（原文 Ablation on Individual Components：去 DSL / 去精修），Portal UX Agent 单设 "bounded vs unconstrained"。
- 建议拆成两节：
  - **RQ2 = 补救能否替代分工**（三配置，回应"对照方案被削弱"）；
  - **§5.x 拆件对比 = 移除修复**（L6 vs L6-NR，可选加 L5b vs L5-NR），证明"构造保证之后修复冗余"。
- 好处：拆件对比一词只出现在该出现的地方，与 §11.4 的术语纪律自洽。

**P1-2 RQ 结构：C 组没有归属，L5b→L6 的代价没有 RQ 承载**

- 现状：RQ1 正确性 / RQ2 补救 / RQ3 代价。C 组（确定性）只写"RQ1 佐证"；"受限结构是否损害表达力"（L5b→L6 内容降级的风险）写在预期表里，但没有 RQ 承接。
- 建议重排为三个 RQ：
  - **RQ1 分工边界对正确性的影响**（A1~A6，含受限结构的代价）
  - **RQ2 补救能否替代分工**（含拆件对比）
  - **RQ3 代价与确定性**（B 组 + C 组）
- 理由：C 组是"可复现"主张的唯一硬数据，挂在 RQ3 比当"佐证"站得住；L5b→L6 的反向风险也有了归属。

**P1-3 "六档穷举"缺一条可检验的判据**

- 现状：只说"只有三个决策"，没说**为什么只有三个**。审稿人会问"文案呢？数据绑定呢？图标呢？"
- 建议补一条判据 + 一张排除表：一个决策要计入分工轴，必须同时满足 ① 输出空间有限且可枚举 ② 错了可被核验。然后把 P3/P4/P6/P7 逐条排除的理由列出来（原型文档 §7.0 已有素材，压缩成半页）。

**P1-4 人工标注是单人，没法核对标注的一致性**

- 涉及：结构参考骨架、mustShow 子集、`F` 校对。
- 建议：抽 20%（约 10 张）双人标注，报 Cohen's κ；κ < 0.6 的条目重新定义判据。

**P1-5 失败卡在指标里怎么算，没写**

- 事实：关兜底后 L1 可能出现生成失败。失败卡在 A4 算 0 覆盖还是从分母里剔除？不同条件失败率不同，口径不一致就不可比。
- 建议写死：**失败 = 覆盖 0、保真 None、计入协议违规**，不要让读者猜。

**P1-6 L5 的实现边界没有定义**

- 事实："丢掉模型写的全部数字"需要一份"数字字段白名单"（width / height / fontSize / padding / borderRadius / maxLines…），否则实现不确定、不可复现。
- 建议：把白名单写进 §3 的 L5 行，作为复现材料。

### 12.3 P2：写作与呈现

- **P2-1 缺机制段**：需要半页解释"为什么程序能保证正确性"——受限结构 → 几何可算 → 协议固定 → 构造即合法。现在这条链散在 §1 与 §2 里，没有集中论述。
- **P2-2 缺失败案例分类**：顶会论文几乎都有 error taxonomy。建议按 `violation code` + 内容缺失类型出一个小表，配 2~3 张真实卡片截图。
- **P2-3 成本只报数值，没有决策价值**：建议加一张"质量-成本"散点（x = 每合格卡 token，y = 合格卡率），或报"覆盖每提升 1% 的边际 token"。
- **P2-4 论文文档里仍有工程内容**：§7（两个修复点、三个开关）对正文无用，压缩成 3 行放附录即可，正文只保留"所有条件共享同一套程序修正"。
- **P2-5 术语**：三个说法（把决定权一项项换手 /拆件对比/ 控制变量的对比）已在 §11.4 定义，但正文第一次出现时要就地给定义，不能只在末尾解释。

### 12.5 建议的执行顺序

1. 先定 RQ 结构（P1-2）与拆件对比位置（P1-1）——这两条决定后面所有表怎么排；

### 13.3 三个不能照搬、必须自己讲清的地方

**（一）为什么不做累加式拆件对比（Widget2Code 那种）**

累加式拆件对比回答"多一个模块值不值"，前提是模块可独立开关、且效果单调叠加。我们的自变量是**同一个决定的归属位置**，不是模块的有无。如果照累加做（L1 → +程序算数 → +模板 → +规则），就变成"我们的系统一步步变好"，那是工程报告，不是位置对比研究。我们的写法必须是：**六个位置、每跳一个阶段、比较位置效应**。这句话要在 Method 里正面写出来，否则审稿人会用图形学/多模态的惯例来要求我们。

**（二）为什么不用 Max IoU / Overlap / FID（LayoutPrompter 那套）**

三条理由，缺一条都会被追问：
1. 那些指标衡量"生成布局与真实布局分布的接近程度"，需要**同任务的大规模参考集**；我们的布局是规范登记的 14 种离散候选、几何由程序求解固定，分布层面没有意义。
2. 我们的几何是**约束求解**的结果，Overlap 恒为 0、Alignment 由模板固定——报这些指标等于报"程序没 bug"，不构成对比。
3. 真正会出错的地方是**文字在剩余宽度里放不放得下**（overflow / clipping / 最小可读字号），这是布局领域指标覆盖不到的。所以我们的几何指标必须是"越界像素 / 裁切像素 / 最小字号"，并说明它来自真实渲染测量（`check_layout`），不是声明比对。

**（三）怎么处理"格式约束的代价"（Let Me Speak Freely 的威胁）**

L1 的提示词必然更长、格式约束更硬。若 L1 表现差，有两种解释：分工错了，或者**格式把模型的语义能力压坏了**。必须能把两者分开，做法二选一（建议都做，成本都很低）：
- **L1-NL 对照**：让模型先用自由文本写计划，再由程序转成三行 JSONL。它和 L1 的唯一差别是"格式约束的施加时机"，和 L5 的唯一差别是"数字由谁算"。
- **报告约束强度**：输入 token 数、schema 字段数、嵌套深度，作为条件属性列进成本表（已在 §4 B 组，但要升格为"解释变量"而不是"成本项"）。

前者若显著优于 L1，说明我们的 L1 被格式约束的代价拖累了，主结论必须打折；后者让读者自己判断这个混淆有多大。**不处理，就是给审稿人递刀。**

| **C-01** | 生成失败的卡怎么算 | **计为不合格**：记 1 条 `generate.failed` 违规；覆盖 = 0；保真不计入；缺全部事实。**不从分母剔除** | 剔除分母会让"经常失败的方案"因为分母小反而好看；这条对 L1 最严格，与"让对照方案带着装备上场"同一原则 | `src/measure.py:build_record`（失败时写入 code）；`exp/metrics/measure_content.py:main`（失败分支） |
| **C-02** | 覆盖的基准 | **拆两档**：A4a 对 oracle 全部事实；A4b 只对人工标 `must` 的必显子集（每卡 2~3 条）。**主结论用 A4b**，A4a 作参考。未标注时 A4b = "未量"，不是 0 | A4a 测的是"像不像金标的完整度"，不是"够不够"；L6 的容量降级会被 A4a 误判成漏 | `exp/metrics/measure_content.py:check`（`coverage_must` 字段）；标注待办 = T09 |
| **C-03** | 保真没有分母（0/0） | 卡面**没有任何数据型片段** → 保真记"不计入"，置 `empty_data` 标志，**空数据卡数单独进主表** | 记 100% 让空卡刷满分；记 0 冤枉合法形态；把排除比例亮出来，两头都不吃亏 | `exp/metrics/measure_content.py:check`（`empty_data`）；汇总列"A5 空数据卡" |
| **C-04** | "合格卡"的定义 | **复合**：协议合规 ∧ 覆盖 ≥ 阈值 ∧ 单节点越界 ≤ 4px。**主阈值 80%**，另报 60% / 100% 两档敏感性。覆盖优先用 A4b，未标注时降级 A4a（表头注明） | 只按协议合规算，就是在奖励"内容少"——B4 原来就栽在这；80% 是当前唯一的主观数，敏感性两档让读者看见结论对它的依赖程度 | `exp/metrics/build_metrics_report.py:_qualified`（三列：合格@60/80/100） |
| **C-05** | 字号缺陷线 | **两条线**：低于 12fp 的节点数（UX 规范线，判违规）+ 低于 10fp 的节点数（金标实测线，判"比金标还差"） | 金标自身存在 10fp 的卡；只用 12fp 一条线，会得出"金标不合格"的自相矛盾结论 | `src/measure.py:static_metrics`、`exp/metrics/measure_geometry.py:_min_font`（`below_12fp` / `below_10fp`） |
| **C-06** | 重采样算不算措辞 | **措辞不同算不一致**（严格口径），并在论文里声明这是**下界**——真实稳定性只会更高；统计量用"N 次全一致率"，不用翻转率 | 保守方向审稿人挑不出"你放宽了"；N=10 时翻转率本身不可信 | `exp/runners/resample_stability.py:canonical`（`type|content_hint` 精确比对，实现本就是严格口径） |

### 15.1 已知会变的东西（提前写下来，免得事后被问）

- **C-02 的 A4b**：现在 oracle 还没有 `must` 标注，A4b 显示"未量"。T09 完成后自动生效，**不需要改代码**，报表会自动从 A4a 切到 A4b。
- **C-04 的 80%**：全表唯一一个拍脑袋的数。所以才有 60% / 100% 两档敏感性——如果三档结论同向，这个数就无关紧要；如果换一档结论翻转，主结论必须声明"依赖阈值选择"。
- **C-06 与语义等价**：严格口径会低估稳定性（"多云"和"天气多云"算不一致）。这是故意选的：放宽口径需要先定义"什么算等价"，而那个定义本身就是一把没校准的尺子。

### 14.7 需人工完成的事项（机器替代不了的）

> 这些事**必须由人做**，理由都写在最后一列：不是"机器做得差"，而是"机器没有判据"。
> 每项都给了输入、输出、时长——拿着就能开工，不需要再讨论。

| 编号 | 要人做什么 | 输入 | 输出 | 时长 | 为什么必须人做 |
|---|---|---|---|---|---|
| **H-01**（对应 T09） | 给报告题集每道题写"要求必须显示哪几条" | 250 道题的提问 + 数据候选（**不看金标产物**） | 每题 2~3 条条目清单 | 3~4h | "该显示什么"是产品判断，不是文本匹配；机器只能判"出现没出现" |
| **H-02**（对应 T04） | 20 张卡做**成对偏好**判断（A 与 B 哪个更好），2 位标注者 | 两个条件的产物截图 | 每对 1 个偏好 + 1 句理由 | 3h | 判"哪张更好"没有客观函数；这是校准 14 把尺子的唯一办法 |
| **H-03**（对应 T05） | 抽 10 张重复标一遍（与 H-02 的标注者交叉） | 同上 | Cohen's κ | 1h | 一致性只有在"两个人独立标同一批"时才成立 |
| **H-04**（对应 T16） | 把失败样本归类、命名成一张分类表 | 各条件的失败卡 + violation code | 失败类型表（含每类的判据与例图） | 2h | 分类学的价值在"类型命名"是否有解释力，机器聚类给不出可命名的类型 |
| **H-05**（对应 §16.2） | 审 85 条无产物样本的归类：是"系统处理不了"还是"采集漏了" | 这 85 条的提问与候选数据 | 一份归类结论 | 1h | 判断缺失原因要看语境，机器只能统计特征 |
| **H-06**（对应 T21） | 审 494 条输入与截图是否含真实姓名/地址/账号/公司信息 | 原始数据 | 去敏感清单（哪几条要打码/替换） | 2h | 敏感信息判定涉及语境，正则抓不全 |
| **H-07**（对应 C-04） | 跑完主表后，看 60/80/100 三档敏感性，拍板主阈值 | 敏感性表 | 一句结论：维持 80% 或改 | 0.5h | 阈值是价值判断；机器只能告诉你"换了会怎样"，不能告诉你"该选哪个" |

## 16. 实验数据：来源、切分与处理

这一章写得比别的章细，原因很直接：方法可以被讨论，数据一旦有偏，结论就不可信，而数据部分最容易被审稿人逐条追问。以下每一份数据干什么用、多少条、为什么这么多、怎么清洗、谁能看到答案，全部写清楚。

### 16.1 为什么没有训练集与验证集

本实验不训练、不微调任何模型，六档用的模型完全相同，"模型能力"这个变量从头到尾没有变化。写 train / validation / test 等于声称做过训练，审稿人第一句就会问"你训练了什么"。

真正需要区分的是**这份数据有没有参与过开发**。按这个标准切，得到四个题集；不按"训练/验证/测试"切。

### 16.2 数据来源与可用量

两批金标，来自同一套生产系统加人工复检：

| 来源 | 提问从哪来 | 产物怎么来 | 有产物的条数 |
|---|---|---|---|
| 真实用户 | 用户问卷收集的原始提问 | 生产系统生成，人工逐条复检 | 433 / 508 |
| 自建 | 按场景自行构造 | 同上 | 78 / 88 |
| 合计 | | | **511** |

产物是 A2UI v0.9 的三个对象（`createSurface` / `updateComponents` / `updateDataModel`），外部给的文件外层包了一个数组，转换时拆成三行。

**一条必须主动披露的事实**：真实用户那批有 75 条没有任何产物，自建那批有 10 条缺 A2UI，合计 85 条不可用。这不能当"随机缺失"处理——如果生产系统是因为处理不了才没生成，那么金标只覆盖了它**能处理**的请求，这个偏倚会把所有档位的得分一起抬高。

所以第一步里专门有一项检查：统计这 85 条的提问特征（长度、是否带数据候选、领域、是否含动作），与可用的 511 条做对比。若分布明显不同，论文必须写明"金标只代表生产系统可处理的请求范围"，不能声称覆盖全部真实需求。

**金标本身的质量也要审计**：这批产物标注为"人工复检通过"，但复检的含义（谁检、按什么清单、单人还是双人）尚未记录在案。P6 安排了一次独立抽检（50 条，按协议合规、内容完整、绑定正确三个清单），错误率超过 2% 时，金标的可信度单独声明。

### 16.3 四个题集

| 题集 | 数量 | 用途 | 开发期能否看答案 |
|---|---|---|---|
| 开发题集 | 100 | 验证实现覆盖了规范的全部分支、写提示词示例、失败诊断 | 能 |
| 报告题集 | 250 | 主表、补救对比、代价指标、稳定性、人工评分 | 不能 |
| 扩展题集 | 60 | 换第二个模型验证方向是否一致 | 不能 |
| 保留题集 | 84 | 42 条用于预先声明的补充跑批，42 条留审稿追加 | 不能 |

100 + 250 + 60 + 84 = 494，即去重后的可用量。

### 16.4 数量为什么这么分

**约束一：总量封顶。** 可用 494 条，四个题集的和不能超过它。报告题集每多 40 条，保留题集就少 40 条，这是唯一的硬取舍。

**约束二：报告题集的大小决定统计功效。** 主表是配对比较（同一道题，六档各做一遍）。配对二分类能测出多大差异，取决于"结果不一致的题占多少、偏向哪一边"。按常见情形估算（约 35% 的题在两档之间结果不同，其中偏向较好一档的比例为 66%–70%）：

| 报告题集 | 能检出的最小差异（约） | 判断 |
|---|---|---|
| 160 | 73 : 27 | 只抓得住大差异 |
| 200 | 70 : 30 | 中等偏大 |
| **250** | **66 : 34** | 中等差异也有八成以上把握 |
| 290 | 65 : 35 | 更稳，但总数不够 |

选 250 而不是 200，是为了让"结构交给程序"这一跳（L5→L6，预期差异最小）不至于因为样本不足被写成"未见显著"。

**多重比较的处理必须提前定**：主比较只有一次（L4→L5，几何交给程序），预设为单次检验、不做校正；其余几跳属次要指标，报 Holm 校正后的结果并注明。这样主结论的检验力不被校正吃掉，次要结论也不虚报。

**约束三：分项报分要求每种布局有足够样本。** 报告题集除总数外还要按布局分组报，所以主要布局每种至少 15 条。250 条才够分。做不到的布局（例如带两个比例环的、四个并列模块的）如实标"样本不足，不下结论"——这是数据本身的上限，不是抽样能解决的。

**约束四：开发题集只需要覆盖，不需要功效。** 规则改由规范实现之后，开发题集不再承担"反推规则"，只做三件事：验证实现覆盖了规范所有分支、写提示词示例、失败诊断。布局本身已绑定尺寸（10 种小卡 + 4 种宽卡），每种 3 条共 42 条，加边界个例约 58 条，合计 100。

**这里有一个降低偏倚的关键选择**：容量常数（画布 150×150 / 300×150、安全区 126×126、双块 134×63、四槽 59×59 等）**直接取规范附录 A 的参考预算，不从开发题集拟合**。这样开发题集影响实验的范围被压缩到"提示词示例"和"实现是否覆盖分支"，而不是"数值调优"。

**代价与限制**：报告题集不是全部数据。可以诚实说明——84 条留后备、60 条做换模型验证，是为了应对审稿追加；若评审要求"用全部数据跑一遍"，那属于追加实验，用保留题集执行。

### 16.5 数据制备流水线（执行进度在此打钩）

两个阶段：程序先把数据加工完，人工集中在冻结前一次做完，最后冻结并把答案移出工作区。共九步；相似的处理已合并（指纹并入体检、格式与裁剪、布局与领域、冻结与移出各并为一步），避免步骤表比数据还长。

分题集（P5）是草稿态：它依赖的布局判定要到人工校验（P6）通过才作数；不过关就改判定规则回 P4 重跑。程序重跑只需几分钟，这个循环是便宜的。

**阶段一：程序（P1–P5）**

- [ ] **P1 体检与偏倚检查**：先对原始数据记总哈希；逐条按八条判据体检，剔除记原因码并报分层统计（按来源、尺寸、领域）；对 85 条无产物样本做特征对比，量化"只挑成功案例"的偏倚。
- [ ] **P2 去重分组**：完全重复、近似重复（阈值跑 0.75 / 0.85 / 0.95 三档，取组数稳定的一档）、同一数据能力加同一组参数，三种判法合并成重复题组；组内选代表，其余标"变体"。
- [ ] **P3 格式统一与输入裁剪**：数组拆三行，数据模型原样保留；输入只留提问、尺寸、数据候选、事件候选、素材候选、标题描述六项，丢弃设备、会话、鉴权、分页、包名、版本。
- [ ] **P4 结构判定**：按规则反推 14 种布局，匹不上标"未判定"；用数据候选的能力标识给每条标领域。两项都是逐条自动标注，无人工。
- [ ] **P5 分题集（草稿态）**：按"布局 × 尺寸 × 来源 × 领域"分层，以重复题组为单位；开发题集按覆盖抽，报告题集按真实比例抽；泄漏检查（报告题集与开发题集最近邻相似度 <0.7）；5 个随机种子各跑一遍验证分布稳定。产出四个题集清单和一份人工校验工作包（体检抽样 25 条、重复题组、布局抽检 50 条两份独立清单、条目候选稿）。

**阶段二：人工（冻结前一次会话）**

- [ ] **P6 人工校验**：复核体检抽样与重复题组；两人独立各判 50 条布局，κ ≥ 0.9 才通过，不过关改规则回 P4 重跑；抽 50 条金标按协议合规、内容完整、绑定正确三个清单复检，错误率 >2% 时金标可信度单独声明；确认去重阈值与种子。
- [ ] **P7 必显条目**：给报告题集每道题写"要求必须显示哪几条"。先试标 10 条校准判据（用户点名的对象、字段、动作必须；核心读数必须；其余可选），再标全部 250 条，双人各标 20 条算一致性。只看提问和数据候选，不看金标产物。

**阶段三：收尾**

- [ ] **P8 冻结与隔离**：四份题集清单、布局判定、条目、重复题组、种子、哈希写入 manifest，编版本号 v1；随后把三个闭卷题集的答案移出工作区（作者执行，记录时间与位置）。冻结后的改动只有两种处理：整轮作废重来，或记 v2 并作废 v1 全部结果。
- [ ] **P9 评测脚本验证**：指标代码先在开发题集上跑通并逐条人工核对，确认算得对，才允许用于报告题集。

P9 之后数据制备结束，进入跑批。

#### P1 的八条判据，以及每条的依据

判据全部是**产物完整性**标准，不是"好不好看"的质量标准——前者是能当真值的必要条件，后者才构成选择偏倚。任何一条不合格的产物拿来当真值，都会把错误同时传给六个档。

| 判据 | 为什么必须有它 |
|---|---|
| 三个对象齐全、surfaceId 一致 | 缺任一对象产物不可渲染，当真值会判错所有档 |
| 组件都在 8 种基础组件白名单内 | 越白名单说明生产系统偏离了协议；当真值等于把协议违规"合法化" |
| 绑定路径能在数据模型里找到 | 悬空绑定在真机上不显示该内容——产物实际表现和它看起来的样子不同 |
| 尺寸可判 | 尺寸是第一个分层维度（2×2 / 2×4），也是容量计算的前提 |
| 每个文字节点可定位 | 定位不了就无法算宽度、行数、越界——几何指标全部失效 |
| 非空卡（组件 ≥3、数据模型有值） | 空卡当真值会系统性抬高"什么都不生成"的档 |
| 提问非空且 ≥4 字 | 空提问无法复现需求，内容指标无从判起 |
| 超长提问（>300 字）单列、不剔除 | 它是"大段原文输入"的真实形态；剔除等于伪造请求分布。保留并作为子组报告 |

#### 每步为什么不可省（写论文时直接引用）

与 16.9 配套：16.9 回答"评审可能问什么"，本节回答"每一步的存在依据"。

| 步 | 存在依据 | 省略它会被问什么 |
|---|---|---|
| P1 体检 | 坏产物当真值会把错误同时传给六个档；分层统计让剔除这次选择本身可见；85 条分析是唯一无法靠设计消除的偏倚，只能量化披露 | "你是不是只挑了成功案例当数据？" |
| P2 去重 | 重复题让高频意图主导主表、功效虚高；三档阈值对比让 0.85 不是拍的 | "重复题让你的 n 是虚的" |
| P3 格式与裁剪 | 数据模型是内容指标真值的唯一来源，必须原样保留；无关字段会给六档引入含量不等的噪声变量 | "档间差异是不是输入差异造成的？" |
| P4 结构判定 | 布局名在产物里已丢失，分层与分项报告都依赖它；领域分布决定泛化主张的边界 | "按布局报的分项呢？领域会不会被一两个业务主导？" |
| P5 分题集 | 数量依据见 16.4；多种子排除"清单恰好运气好"；泄漏检查排除开发题集变体渗入 | "换个随机种子，报告题集还长这样吗？" |
| P6 人工校验 | 判定规则由作者编写，作者复核不构成验证；双人独立加一致性才是验证 | "规则你自己写的，也是你自己核的？" |
| P7 必显条目 | 内容指标的分母必须独立于被测系统与金标产物，否则循环论证 | "你的标准答案是不是自己的系统给的？" |
| P8 冻结与隔离 | 预注册是防事后调整的唯一手段；答案只要在工作区，"没看过"就无法自证 | "跑完批你改过判据吗？""你怎么证明没看过？" |
| P9 评测验证 | 指标代码也是实验装置，未验证可能把六个档一起算错，而且悄无声息 | "你的指标本身算对了吗？验证过吗？" |

### 16.6 人工环节的判据（对应 P6、P7 与两份名单）

人工步骤只有两个会话（P6 校验、P7 写条目），但每一步都有硬判据：

| 环节 | 硬规矩 |
|---|---|
| 布局抽检（P6） | 两人**独立**判，先不互相看；κ ≥ 0.9 才通过 |
| 金标抽检（P6） | 按协议合规 / 内容完整 / 绑定正确三个清单；错误率 >2% 单独声明 |
| 写"要求必须显示的条目"（P7） | **只看提问和数据候选，不看金标产物**；试标 10 条先校准判据；双人各标 20 条报一致性；必须在报告题集首次跑批之前完成 |

两份编号名单的规则：

| 名单 | 数量 | 什么时候定 | 规则 |
|---|---|---|---|
| 哪 12 道题反复问 10 遍 | 12 | P8 冻结后 | 从报告题集按"布局 × 尺寸"分层抽；温度等采样参数固定并记录 |
| 哪 40 对卡片请人盲评 | 40 对 | **跑批之后**（要按产物配对） | 同一道题不同两档的产物成对，覆盖 L4 vs L5、L5 vs L6 等关键跳；随机抽 |

**为什么条目不能看金标产物**：看了就是拿被测系统的答案当标准答案。金标卡自己也可能漏显示一条，跟着它写，这个指标就失去了独立判据的意义。

**为什么必须早于跑批**：跑完再按结果补写，等于按结果定判据，指标作废。

### 16.7 可见性：谁能看到答案

三个角色要分开说，混在一起就会做成假隔离：

| 角色 | 能看到什么 |
|---|---|
| 生成模型（六档运行时） | 只有输入。任何题集都一样，金标产物、布局判定、字段优先级都不进提示词 |
| 开发期的人（作者） | 只有开发题集的答案。报告、扩展、保留三个题集的答案不在工作区 |
| 评测脚本 | 跑批结束后读答案算指标，只输出聚合结果，不输出单条对照 |

**物理隔离怎么做**：分题集完成后，把报告/扩展/保留三个题集的答案目录移出工作区（作者自行移到工作区之外的位置），工作区只留这三份的输入。跑批只读输入，所以不需要答案；评测时由作者执行脚本，脚本读外部目录，只把聚合指标交回。

**代价要接受**：报告题集跑完之后，不能再做逐条失败分析。失败分析只能用开发题集，而且必须在报告题集首次跑批**之前**做完。这条限制换来的是"跑批时确实没有答案"，值得。

**声明一个残余风险**：开发题集与报告题集来自同一批数据，作者在写提示词时会看到 100 条开发题集的答案。所以论文必须写明：机制来自规范、容量常数来自规范附录 A，开发题集只影响提示词示例。这是这套分法能站住的前提，不能含糊。

### 16.8 预先定下的三条调整规则

跑批之后再定规则就是事后挑数据，所以现在写死：

1. **覆盖不足**：若 T5 实测显示某些布局凑不到"每种 × 尺寸 3 条"，从**保留题集**调，不从报告题集调。
2. **接近显著的补充**：主比较若 p 落在 0.05–0.10，用保留题集的第一半（42 条）补跑一次，只允许一次，结论里注明这是预先声明的规则。
3. **样本不足不下结论**：分项报分时，某布局样本 < 8 条只报数字与样本量，不作推断。

## 17. 实验工程结构（代码怎么摆，为什么这么摆）

### 17.1 一个项目、两个区

```
cardgen-proto/
├── src/        产品区：第六档（L6）的本体（文件名带 M1_ / P1_~P7_ 前缀），一行实验代码都不进
├── exp/        实验区：另外三个方案的实现、跑批、度量、人评；只单向依赖 src
├── prompts/    提示词：产品与实验共用（共享片段只有一份）
├── rules/      规则库：布局 / 角色字号 / 排法 / 主题 / 枚举 / 白名单（按 UX 规范实现）
└── data/       原始数据（incoming/）+ 切分后的四个题集（dataset/）
```

为什么不是"原型一个仓库、论文一个仓库"：六档共享的东西太多（提示词拼装、解析、校验、修复、度量、排版测量），拆两个仓库只能靠拼路径互相引用，而且"同一套程序、只换决定权"这个主张在代码层面会被物理分割削弱。放同一个项目里，**差异只在条件表**，这才是论文要讲的事。

代价是产品仓库长期带着实验代码，所以必须有剥离机制（见 17.4）。

### 17.2 六档 = 一张表的六行

**方案不是实体，阶段才是。** 五个阶段各有两三种实现，方案只是"每个阶段选哪个实现"：

| 阶段 | 输入 → 输出 | 可选实现 |
|---|---|---|
| 内容 | 用户这句话 + 数据 → 语义计划 | `model_extract`（L2~L6 共用，唯一一份） |
| 结构 | 语义计划 → 组件树骨架 | `model_free`（L2~L5）/ `model_pick`（L5b）/ `program_route`（L6） |
| 几何 | 组件树 → 带字号、换行、截断、丢弃的树 | `model_solve`（L2~L4）/ `program_solve_plan`（L5、L5b、L6） |
| 主题 | 带几何的树 → 带色值的树 | `model_theme`（L2、L3）/ `program_theme`（L4~L6） |
| 发射 | 带色值的树 → 三行 JSONL | `model_emit`（L2）/ `program_jsonl`（L3~L6） |

L1 不在这张表里：它整档标 **`one_shot`**——模型一次生成直接出终产物，没有中间表示可拆。给它编五个中间表示、每段调一次模型，那已经是 L2，不是"全包"。

条件表在 `cardgen-proto/exp/conditions.py`，**这张表同时就是论文附录要的"条件 → 配置"映射表**（`appendix_table()` 直接生成），不需要手写，因此永远不会与实际跑批不一致。

为什么不按方案分文件（`l1_full.py`、`l2_recalc.py`……）：只有两种结局，都错——

- 后一个方案 import 前一个的实现 → **包含关系**：改一处另一处跟着变，说不清差异，审稿人会怀疑"你的两档是不是共享了实现"；
- 各写一遍 → **重复实现**：两份代码质量不同，就是"故意削弱对照方案"的把柄。

按步骤分文件则天然消除这两点：同一步骤只有一个实现时，六档必然共用它。

**五个阶段的接口契约**（阶梯能成立的前提：每阶段输入输出形状固定，否则同一阶段的两种实现会各写各的）：

| 阶段 | 输入 | 输出 |
|---|---|---|
| 内容 | 用户这句话 + 数据 | 语义计划 `{domain, items[], actions[], objects[], size}`——不含任何坐标、字号、颜色 |
| 结构 | 语义计划 | 组件树骨架 `{skeleton_id, slots{...}}`——有区块与槽位，无字号坐标 |
| 几何 | 组件树（骨架，或模型自由写的树） | 同一棵树 + 每个文本节点的 `fontSize / maxLines / truncate / dropped` |
| 主题 | 带几何的树 | 同一棵树 + 每个节点的色值（主题 id 必须在 4 套枚举内） |
| 发射 | 带色值的树 | 三行 JSONL（A2UI v0.9） |

关键约束：**每一阶段的输入输出都是"同一棵树 + 更少的自由度"**——结构加上谁装谁，几何加上字号与截断，主题加上色值，发射只做序列化。这样同一阶段的两种实现可以互换，外部行为不变。

**五个抽象阶段包住了哪些实际环节**（否则条件表落不到代码）：第六档（L6）走的是 `pipeline.generate()` 里的 M1 + P1~P7 共七个环节，论文的五个阶段是它们的归并：

| 抽象阶段 | 实际环节（L6） | 该阶段产物 |
|---|---|---|
| content | M1 语义抽取 + P1 归一化 | 语义计划（entries） |
| structure | P2 骨架路由 + P3 槽位装配 | 组件树骨架（regions / slots） |
| geometry | P4 角色规格 + P5 容量求解与装配 | 带字号与截断的 IR |
| theme | P6 主题装配 | 带色值的 IR |
| emit | P7 发射 | 三行 JSONL |

**组装只有一个循环**，代码里不存在任何按方案分支：

```python
def run(cond, query, llm):
    spec = CONDITIONS[cond]              # 一行
    if is_one_shot(cond):                # 不分解档：一次生成，直接出终产物
        return DISPATCH[("all", "one_shot")](query, llm)
    out = query
    for step in STEPS:                   # content → structure → geometry → theme → emit
        out = DISPATCH[(step, spec[step])](out)
    return out
```

两点值得注意：循环体里**没有 `if cond == "L5"` 这类分支**，差异 100% 来自 `spec` 那四个字符串；代码里唯一的档位判断是"是否整档不分解"，它只决定走单步还是四步，**不决定任何一步用谁**。

**现状**（如实记录）：这段组装器还没写。当前 `run_condition.py` 是让 L6 直通 `pipeline.generate()`（整条管线一次调用），条件表目前只用于生成附录映射表与结构检查。要让它真按表组装，还差两件事：把产品管线拆成可按阶段进入的入口、把 L1~L5 与 L5b 的实现写出来。

实现清单与状态（"待落地"表示只有接口、还没写）：

| 阶段 | 实现 | 谁用 | 状态 |
|---|---|---|---|
| 整档 | `one_shot` | L1（不分解） | 待落地（模型一次出三行 JSONL，无中间表示） |
| 内容 | `model_extract` | L2~L6（唯一一份） | 待落地（先复用 `src/M1_extract.py` 的通道） |
| 结构 | `model_free` | L2~L5 | 待落地 |
| 结构 | `model_pick` | L5b | 待落地（程序校验并采用模型给的骨架 id） |
| 结构 | `program_route` | L6 | 已有（`src/P2_skeleton_route.py`） |
| 几何 | `model_solve` | L2~L4 | 待落地（模型给字号与截断，拿不到真实宽度） |
| 几何 | `program_solve_plan` | L5 / L5b / L6 | 已有（`src/P5_capacity.py` + `src/P5_assemble.py`） |
| 主题 | `model_theme` | L2 / L3 | 待落地（模型选色板并给色值） |
| 主题 | `program_theme` | L4~L6 | 已有（`src/P6_theme.py`） |
| 发射 | `model_emit` | L2 | 待落地（模型直接写 JSONL） |
| 发射 | `program_jsonl` | L3~L6 | 已有（`src/P7_emit.py`） |

调度器还没写（随实现一起落地），但接口已经定死：它只读条件表，按 `(步骤, 实现名)` 找到对应函数依次调用，本身不含任何条件判断。**新增一个实现 = 写一个函数 + 在条件表登记一行**，调度器一行不改。这条约束就是"方案不是实体"在代码里的落点：一旦某档需要改调度器，说明它偷偷变成了独立流程。

### 17.3 模型调用：只统一"怎么调"，不统一"调什么"

| 层 | 管什么 | 几份 |
|---|---|---|
| 调用通道（`src/M1_extract.py`） | 端点、超时、重试、温度、token 计量、时延、原始响应留存、模型版本 | **一份** |
| 任务（`prompts/` + `exp/steps/*/`） | 提示词模板、期望输出格式、解析、结果校验 | 每类任务一份 |

三个附带约束：

- **调用次数归跑批脚本**，不归通道。主实验的调用次数按档不同（L1/L6 各 1 次、L2 五次、L3 四次、L4 三次、L5 与 L5b 各两次）；补救组的 1~2 次修复由跑批循环。通道里的失败重试单独计数，不许混进"调用次数"。
- **提示词的共享部分文件级唯一**：约束清单（`prompts/_constraints.md`）与示例素材（`prompts/_fewshot.md`）六档拼同一份，不许各写一遍——这是论文公平性第 1、2 条在代码里的落点。
- **条件带来的信息差必须显式**：L5b 让模型看到 14 种布局的目录（L5 的模型是自由写，没见过这份目录），这属于"结构自由度"这个变量的固有信息差。这条只能写进附录，不能藏着。

**跑批产物与记录**（缺了这三样，出问题时无法回溯）：

- 产物落在 `runs/exp/<条件>/<时间戳>/`，含 `records.jsonl`（逐条结果）、`cards/*.jsonl`（每张卡的终产物）、`run_meta.json`（模型版本、温度、提示词哈希、时间）；
- 每条记录必须写清**这一步用了哪个实现**（从条件表抄），论文附录的"条件→配置"表由此自动生成，不靠手写；
- 提示词哈希进 `run_meta.json`：跑批后提示词若有改动，那一批数字作废。

### 17.5 复现包：从仓库组装，不手工维护

`paper/release/build.py` 每次从当前仓库挑子集打包（代码 + 数据 + 三条命令的说明），不维护第二份代码。包里只留三条命令：跑一条、跑主表、出统计。零第三方依赖（Python 3 标准库）是这套代码最实在的优点——评审装个解释器就能跑。双盲版加 `--anonymous`，去掉作者与单位信息。

### 19.1 方案不是实体，是组合

六个条件不是六套程序，而是同一张条件表的六行（§17.2）。**这样做本身就是论证**：如果六档各有一套实现，读者无法排除"作者把某一档写得更好"；分步的三档（L2~L6）共用同一批步骤实现时，"差异只在归属"这件事在代码结构上就成立了。

反过来，如果哪天有人提"给第六档单独优化一下"，那就是破坏这条约束——必须先改条件表，而不是改某一条路。

### 19.2 共享部分文件级唯一

六档共用的东西必须只有一份：模型通道、约束清单、示例素材、校验器、度量代码。检查方式见 §17.4 的四条断言。

不用它的后果很具体：某一档少给一条约束、或者示例少一个，比较就不公平，而这种事在文字里是看不出来的，只有文件级唯一才能防住。

### 19.3 不对称必须显式化，不许"抹平"

这套设计里天然存在三处不对称，全部写进论文，不假装公平：

| 不对称 | 内容 | 处理 |
|---|---|---|
| L1 / L5 没有计划层 | 入口修正作用于"结构计划"，这两档没有这一层数据 | 用补救对照（§8）量化它，残余写进限制 |
| L1 没有中间表示 | 模型一口气出整张卡，没有步骤可拆 | 整档标 `one_shot`（不分解），如实体现在条件表上（§17.2） |
| L5b 多知道一份布局目录 | 同一次调用里模型多看到 14 种布局的说明 | 附录写明；它属于"结构选择权"这个变量的固有信息差 |

"抹平"（比如硬把 L1 拆成五步、每步调一次模型）看起来公平，实际上改变了实验条件，而且掩盖了真正要讨论的东西。

### 19.4 数据分法就是证据分法

开卷 / 闭卷 / 冻结三类数据（§16），各自回答一个不同的问题：主结果、抗调参质疑、指标口径。混在一起报，等于没有证据。

### 19.5 代码可剥离 = 结论可迁移

产品区与实验区分开（§17.1），并且有剥离测试。意义不只是工程整洁：它证明"本文的方法可以落成一个只保留第六档的产品"，而不是一篇只在实验室里成立的论文。评审最常问的"这套东西能上生产吗"，答案在目录结构里。

### 19.6 口径与代码同源

三处同源：条件表 = 附录映射表（同一份 `conditions.py`）；指标口径 = 代码常量（C-01~C-06 写在 §15，实现落在 `src/measure.py`）；阈值 = 一处定义、多处引用（80% 只出现一次，敏感性分析换参数而不是改代码）。

同源的好处是"论文写的"和"跑出来的"不可能不一致——这是可复现性的最低要求，也是最容易被忽略的一条。

### 19.7 目录与命名必须持续与论文对应（长期原则）

**原则**：项目的目录结构与文件命名，是论文的一部分，不是工程的私事。**每当论文的结构发生变化，代码结构要跟着改；每当代码结构发生变化，论文要跟着改。两边不允许出现"论文里有、代码里找不到"或"代码里有、论文说不清它是什么"的东西。**

#### 为什么把它列为原则，而不是一次性整理

一次性整理只能解决"今天对不对得上"，解决不了"三个月后还对得上"。这类漂移的典型过程是：先临时加一个 `misc/`，再塞一个 `draft_l2.py`，然后在论文里把这一档换个名字——半年后没人能回答"论文第三档的实现在哪"。到那一步，评审问的第一个问题（"你的代码在哪、是不是你写的那一套"）就无法用目录回答，而要靠口头解释，这在评审面前是减分的。

#### 四条可执行的规定

| # | 规定 | 检查方式 |
|---|---|---|
| 1 | **新增任何目录或文件，必须能回答"它对应论文的哪一节 / 哪个环节"**；答不上来的，先想清楚再建，不要先建了再说 | 人工：提交说明第一行写这句话 |
| 2 | **环节相关的文件必须带环节号**（`M1_`、`P1_`~`P7_`），基础设施文件不带号 | `ls src/` 一眼能数出 M1 + P1~P7 |
| 3 | **改名 / 移动必须同步两份正本**：本文 §17（含 §17.6 的评审导航表）与设计正本 §13（目录树 + §13.1 命名约定）。根 README 只做入口、不写事实，不在同步清单里 | 全库 grep 旧名，必须为空 |
| 4 | **名字不承载版本，只承载含义**：不用 `v2` / `new` / `old` / `final` / `tmp`；废弃文件进 `data/legacy/` | 目录名扫描 |

#### 检验方式（论文定稿前跑一遍）

1. 打开本文 §17.6 的评审导航表，逐行确认路径真实存在；
2. `grep` 一遍已废止的名字（如 `registry/`、`fixtures/`、`src/llm.py`），结果必须为空；
3. 从论文 §3 的六档定义出发，反查每一档的实现文件，必须能一路点到代码；
4. 反向抽查：从 `src/` 与 `exp/` 里任选五个文件，必须能说出它属于论文哪一节。

四条都过，才算"结构仍然与论文对应"。任何一条不过，说明中间发生过未同步的结构变更。

#### 文档只留正本（迭代期不建衍生文档）

原则：**迭代期只有三份正本加一个根 README，别的文档一律不建。**

| 保留 | 写什么 | 体量 |
|---|---|---|
| 设计正本 | 系统设计、规则库、目录与命名、模型配置 | 1600 余行，唯一技术依据 |
| 论文正本（本文） | 实验设计、指标、口径、工程结构 | 1000 余行，唯一实验依据 |
| UX 规范 | 字号间距档位、few-shot 样张 | 规范与素材 |
| 根 `README.md` | 定位、三条命令、指向三份正本 | 30 行 |

**为什么不建目录说明、使用手册、贡献指南**：文档的成本不在写，在"改了代码要记得同步"。每多一份就多一个会过期的副本，而过期的副本比没有更糟——本项目真实发生过：`paper/README.md` 长期写着"实验脚本还在 `cardgen-proto/tools/`"（实际早已迁进 `exp/`），`exp/` 下还一度按目录层级摊开五份说明，读的人要连开五个文件才拼出全貌。这些内容不是错的，是**没必要单独存在**：接口契约进 §17.2，跑批产物规范进 §17.4，数据文件的来源去向进设计正本 §13.3。

**发布前再补的三类**（届时从正本抽取，一次性生成，几小时的事）：

1. 安装与复现手册（复现包根目录那份，`release/build.py` 已能生成）；
2. 目录说明 / README（仓库门面、子目录导览）；
3. 贡献指南与许可。

自检判据：**如果一条信息改一次要改多个文件，它就放错了地方**；**如果一份文档只是把别处的话重说一遍，它就不该存在**。

#### 与 §19.1、§19.5 的关系

三条是同一件事的三个层次：§19.1 说**方案不是实体、步骤才是**（逻辑层）；§19.5 说**实验区可整块剥离**（部署层）；本节说**名字要能被评审读懂**（表达层）。三者缺一，另两条的效果都会被打折——尤其本节：代码结构再干净，如果名字对不上论文，评审仍然要花力气去猜，而评审通常不会花这个力气，他会直接怀疑实验的真实性。
